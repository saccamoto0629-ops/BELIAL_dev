# PR 本文テンプレート(Skill 参照資料)

BELIAL Issue 実装 PR の本文は、最低限このテンプレートの見出しをこの順で埋める。項目の省略は不可。該当なしの場合も「なし」とその根拠を書く。

```markdown
## Summary

<!-- 何を・なぜ変更したか。Issue 番号と目的を 2〜5 行で -->

## Changed files / affected components

<!-- 追加・変更・削除ファイルの一覧と、影響を受けるコンポーネント/レイヤー。
     影響範囲調査で見つけた参照元も書く -->

## Tests executed and results

<!-- コード変更時: 実行したコマンドと結果を対象 → 関連 → 全体の順で。件数・pass/fail を実測値で書く。
     docs / Skill のみの変更時: 実施した直接検証(frontmatter・リンク・参照パス・構造等)の内容と結果を書く。
     全体 pytest は実行・非実行のどちらでも理由を明記する(実行しても直接検証の代替にしない)。
     実行しなかったスイート・検査は理由を明記する。失敗は失敗のまま書く -->

## Documentation impact

<!-- 更新した docs の一覧。更新不要なら「影響なし」とその根拠 -->

## Known limitations / remaining work

<!-- 割り切った制約、未確認事項、フォローアップ Issue にすべきこと。「なし」で済ませる場合は
     本当に無いことを確認してから書く -->

## Issue との対応関係

<!-- 対象 Issue 番号。受け入れ条件を 1 件ずつ引用し、充足/未充足と根拠を書く -->
```
